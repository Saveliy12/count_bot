## 2026-10-21 — Фундамент backend

- **Задача:** собрать основу монолита для семейных расходов.
- **Изменено:** PostgreSQL-миграции (`families`, `users`, `expenses`, 14 категорий),
  доменные модели с `decimal`, сервис с owner/family-доступом, репозитории и REST API
  панели; health/ready, request ID, логирование, graceful shutdown.
- **Как работает теперь:** REST API отдаёт траты семьи, создаёт/меняет/удаляет их,
  проверяет суммы, категории и даты; миграции применяются при старте приложения.
- **Проверено:** unit-тесты, интеграционные тесты на временной схеме PostgreSQL,
  `go vet`, `go build`, `-race`.
- **Ограничения / дальше:** нет UI и Docker Compose; панель без авторизации — решение
  для локального демо.

## 2026-10-21 — Docker-образ приложения

- **Задача:** собрать воспроизводимый runtime-образ без секретов и лишних файлов.
- **Изменено:** `Dockerfile` (multi-stage, Go 1.26.9 → Alpine 3.22), `.dockerignore`.
- **Как работает теперь:** сборка статического бинарника с `CGO_ENABLED=0`, `-trimpath`
  и stripped-символами; runtime-образ содержит только бинарник и CA-сертификаты,
  запускается от UID/GID 10001. Миграции встроены в бинарник через `go:embed`,
  отдельное копирование не нужно.
- **Проверено:** `docker build` успешен, образ ~21.6 MB, внутри нет `.env`,
  пользователь не root, бинарник статический.
- **Ограничения / дальше:** Docker Compose и проверка запуска с PostgreSQL — следующий этап.

## 2026-10-21 — Docker Compose

- **Задача:** поднимать приложение и PostgreSQL одной командой, не смешивая локальный
  DSN с адресом БД внутри контейнерной сети.
- **Изменено:** `compose.yaml`, `.env.example`, `AGENTS.md`.
- **Как работает теперь:** PostgreSQL имеет healthcheck и named volume; приложение
  стартует после `service_healthy`, применяет embedded-миграции и проверяется через
  `/readyz`. Наружу открыты только loopback-порты; для контейнера используется
  `COMPOSE_DATABASE_URL`, для локального `go run` остаётся `DATABASE_URL`.
- **Проверено:** изолированный project name и временные порты; миграции 0–2; создание,
  чтение, изменение и удаление траты через API; graceful stop; сохранение данных после
  `docker compose down` и повторного запуска.
- **Ограничения / дальше:** веб-панель и README; `docker compose down -v` удаляет данные
  и допустим только для тестового project name.

## 2026-10-21 — Telegram-бот и LLM-парсер

- **Задача:** принимать траты естественным языком, не давая модели доступа к данным.
- **Изменено:** Groq-клиент со strict JSON Schema, `llm.Intent`, промпт, `LLMProcessor`;
  регистрация пользователя из Telegram; create/list/update/delete/clarify.
- **Как работает теперь:** сообщение → LLM возвращает типизированное намерение → Go
  валидирует, ищет владельца и выполняет действие; суммы/даты проверяются в Go.
- **Безопасность:** удаление только после подтверждения «да/нет»; атомарное удаление
  по снимку (`updated_at` и остальные поля); точное совпадение суммы; поиск цели по
  дате/категории; проверка `old_amount`; итоги списков через SQL `SUM/COUNT`;
  «последняя» трата — по `created_at`.
- **Устойчивость:** общий timeout LLM, retry при 429/5xx, `reasoning_effort: low` для
  GPT-OSS и увеличенный `max_tokens`, чтобы strict JSON не обрезался.
- **Проверено:** unit/DB-тесты, `-race`, живой сценарий create → list → update → delete
  с Groq; eval-набор 33 фразы, целевая выборка **10/10**, полный прогон 33/33 пока
  не зафиксирован.
- **Ограничения / дальше:** pending-состояния в памяти; нет нескольких трат в одном
  сообщении; нет дедупликации Telegram update; впереди Compose, UI и README.

## 2026-10-21 — Итоги по семье в списке трат

- **Задача:** показывать в панели точную сумму и количество по текущим фильтрам, а не
  только по загруженной странице.
- **Изменено:** family-scoped `SummaryByFamily` в repository и service; ответ
  `GET /api/v1/expenses` дополнен полями `total` и `count`.
- **Как работает теперь:** список и агрегат считаются по одинаковым фильтрам
  (`user_id`, период, категория); `total` — строка с двумя знаками после запятой.
- **Проверено:** unit-тесты API/service, интеграционные тесты PostgreSQL,
  `go test ./...`, `-race`, `go vet`.
- **Ограничения / дальше:** демо-участник для пустой Compose-БД и статическая панель.
